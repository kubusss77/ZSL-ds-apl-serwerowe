Zadanie 1 

W folderze "static" utwórz stronę index01.html zawierającą trzy linki (a href) z parametrami: postac oraz lvl.

Oceniane działania: 

1. [1 pkt] - po uruchomieniu adresu /index01 serwer poprawnie wyświetla plik index01.html

2. [1 pkt] - po kliknięciu w link (np. /wybor?postac=mag&lvl=10), serwer wyświetla stronę z odebraną nazwą, poziomem 

3. [1 pkt] - oraz pasującym zdjęciem (.jpg) pobranym z serwera
obrazki:
Wojownik: unsplash.com/s/photos/warrior
Mag / Czarodziej: unsplash.com/s/photos/wizard
Łucznik: unsplash.com/s/photos/archer

Zadanie 2

W folderze "static" utwórz stronę index02.html, która przesyła dane rekruta i wyświetla odpowiedź JSON z serwera.

Oceniane działania: 

1. [1pkt] - formularz wysyła dane POST (fetch): {"rekrut": "...", "klasa": "...", "sila": 10} - widać console.log na serwerze

2.  [1pkt] - serwer dopisuje dane do pliku, a następnie odsyła dane o strukturze:

{ 
  "armia": ["rekrut1", "rekrut2"], 
  "statystyki": { "liczbaOsob": X, "sredniaSila": Y } 
}

Wynik ma zostać wyświetlony na stronie w tagu <pre> 

Zadanie 3: 

Cel: Stworzenie endpointu API, który pobiera dane z trzech różnych systemów jednocześnie. 

1. [1 pkt] Logika promises:

- funkcja sprawdzSystem() jest napisana poza createServer()
- funkcja sprawdzSystem() musi zwracać "new Promise"
- Musi symulować opóźnienie (setTimeout) w zakresie od 500ms do 3000ms
- Warunek błędu: Jeśli wylosowany czas odpowiedzi przekroczy 2500ms, obietnica musi zostać odrzucona (reject) z komunikatem: "System [Nazwa] przekroczył limit 2500ms - (timeout)".

2. [2 pkt] - Promise.all:

- Serwer reaguje na ścieżkę /pobierz-oferty
- Uruchamia 3 x funkcję sprawdzSystem dla (Kino, Teatr, Koncert) równolegle za pomocą Promise.all.
- Sukces: Jeśli wszystkie systemy zdążą w czasie < 2.500ms, serwer wysyła status 200 i JSON: { "status": "Sukces", "oferty": [...] }.
- Błąd: Jeśli choć jedna obietnica zostanie odrzucona (czas > 2500ms), serwer musi przechwycić błąd i wysłać status 500 z opisem .

Metoda testowania : przeglądarka:

http://localhost:3000/pobierz-oferty

Przykład poprawnej odpowiedzi:
{ "status": "Sukces", "oferty": [ {"system": "Kino", "bilety": 12, "czas": 850}, ... ] }

Przykład błędu (gdy któryś system wylosuje > 2500ms):
{ "status": "Błąd krytyczny", "powod": "System Teatr nie odpowiedział w czasie 2500ms -  (timeout)" }

Zadanie 4:

Cel: Stworzenie bezpiecznego endpointa na serwerze, który rozpoznaje użytkownika i nadaje mu uprawnienia w zależności od przesłanego klucza.
mamy dwa osobne middleware authGuard i dataPrep() oraz createServer()

1. [1 pkt] - routing i Identyfikacja - middleware authGuard():

- Serwer reaguje wyłącznie na ścieżkę /index04. Każdy inny adres (np. /home) kończy się błędem 404.
- Identyfikacja użytkownika odbywa się przez nagłówek x-api-key:
- Klucz ADMIN123 -> ustawia w obiekcie żądania (req) rolę admin.
- Klucz USER456 -> ustawia w obiekcie żądania (req) rolę user.
2. [1 pkt]  - personalizacja - middleware dataPrep():

- Middleware odczytuje rolę i dopisuje do obiektu req szczegóły dostępu:
- Dla admina: poziom 10, strefa Hangar A, opis: jest dostęp
- Dla usera: poziom 1, strefa Korytarz, opis: brak dostępu
- Serwer odsyła do klienta obiekt JSON z kompletem tych danych (rola, strefa, poziom, opis).

Metoda testowania : PowerShell:

a) test Administratora:
Invoke-RestMethod -Uri "http://localhost:3000/index04" -Method GET -Headers @{"x-api-key"="ADMIN123"}

rola  strefa   poziom opis
----  ------   ------ ----
admin Hangar A     10 Pełny dostęp

b) test Użytkownika:
Invoke-RestMethod -Uri "http://localhost:3000/index04" -Method GET -Headers @{"x-api-key"="USER456"}

rola strefa   poziom opis
---- ------   ------ ----
user Korytarz      1 Ograniczony dostęp

c) test bez klucza
Invoke-RestMethod -Uri "http://localhost:3000/index04" -Method GET 

rola  strefa      poziom opis
----  ------      ------ ----
guest Poczekalnia      0 Brak dostępu

d) test błędnej ścieżki (powinien zwrócić błąd 404):
Invoke-RestMethod -Uri "http://localhost:3000/test"

Invoke- RestMethod:                                                                                                      
{
  "error": "Not Found",
  "message": "Serwer reaguje tylko na sciezke /index04",
  "requestedPath": "/test"
}
